# Image hosting

Almost every photo on this site is still hot-linked from the old WordPress domain:
`https://www.skydream.gr/wp-content/uploads/...`. GoCuba is the redesign skydream.gr is
meant to redirect to, so the new site currently depends on the old one staying up.

Scale: ~1,450 references across `src/`, which dedupe to **316 distinct URLs / 313 distinct
source files**. `src/content/records.ts` holds 741 of them; the rest are spread over 15
components (`HomePage.tsx` has 16, `AiItineraryCreator.tsx` 6).

## Current state (checked 2026-09-12)

**The redirect is not in place yet.** `https://www.skydream.gr/` still returns 200 and
still serves the old WordPress site. The only 301s observed are `http://` → `https://`
canonicalisation, which is routine. `/wp-content/uploads/` serves files normally.

So nothing is broken today, and the images are not yet at risk.

## What protects the site (do this when the redirect is configured)

Whether the images survive the redirect depends entirely on how it is implemented:

| Redirect style | Effect on `/wp-content/uploads/` |
| --- | --- |
| WordPress plugin / PHP-level | Static files never reach PHP — they keep serving. Images survive. |
| Server-level catch-all (`.htaccess`, nginx) | Catches asset requests too. **Every image breaks at once.** |
| DNS cutover, cancelled hosting, lapsed domain | Everything breaks regardless. |

If the redirect is done at server level, exclude the uploads directory. Apache:

```apache
RewriteEngine On
# Keep serving media so the GoCuba site's images do not break.
RewriteCond %{REQUEST_URI} !^/wp-content/uploads/
RewriteRule ^(.*)$ https://gocuba.travel/$1 [R=301,L]
```

nginx:

```nginx
location ^~ /wp-content/uploads/ {
    try_files $uri =404;          # serve media directly, never redirect it
}

location / {
    return 301 https://gocuba.travel$request_uri;
}
```

This is a zero-code-change fix: all ~1,450 references keep working. The trade-off is that
the old hosting must stay paid and running indefinitely, purely to serve images. That is
why the migration below is still worth doing eventually.

## Migrating the images (not urgent, not yet scheduled)

**Recommended destination: `public/` in this repo.** It is the only option that ends the
external dependency outright, it needs no new vendor, DNS record or credentials, Netlify
already CDN-serves `public/`, and the repo *already* self-hosts images this way
(`public/visa/`, `public/espa-banner.jpg`). Images do not churn, so the repo weight is a
one-time cost — estimated 40–80 MB for 313 files, but **measure before committing**.
A dedicated asset domain or Cloudinary also works and avoids the repo weight, at the cost
of a vendor or DNS setup plus a `remotePatterns` entry.

Steps:

1. **Pull the files down** — dedupe first; 1,450 references are only 313 files.
2. **Rewrite `records.ts` at the generator, never by hand.** That file is generated by
   `scripts/generate-content.py` from the `_raw_*.json` WordPress exports, so a hand-edit
   is lost on the next regeneration. Every image URL already funnels through one helper:

   ```python
   def https(url: str) -> str: ...       # scripts/generate-content.py
   ...
   "images": [https(u) for u in item.get("images", []) if u],
   "thumb":  https(item.get("thumb") or (item.get("images") or [""])[0] or ""),
   ```

   Adding a `rewrite_asset()` alongside `https()` covers all 741 occurrences and survives
   regeneration. Leave the raw exports carrying their original URLs — that is correct.
3. **Edit the 15 component files directly** — they are hand-written, not generated.
4. **Update `images.remotePatterns` in `next.config.ts`** for the new host, and drop the
   skydream.gr entries once nothing references them. (It currently lists `www.skydream.gr`
   and `skydream.gr` twice each — four entries, two unique. Worth deduping in passing.)

### Two things that will bite

- **25 filenames contain Greek characters**, e.g.
  `σχηματισμοί-mogotes-κοιλάδα-Βινιάλες-skydream-εκδρομή-Κούβα.jpg`. They need
  URL-encoding care on download, and are best normalised to ASCII slugs on the way in.
- **278 of the 316 URLs are WordPress size variants** (`-1024x576`), and 10 are `-scaled`.
  Decide deliberately whether to keep the WP-resized files or pull the originals and let
  `next/image` do the resizing.

### Already handled

Some records point at the ESPA/EU funding banner. `src/lib/content.ts` filters those out
via its `BANNER_IMAGE` regex, so exactly one of the 316 URLs needs no migration.
